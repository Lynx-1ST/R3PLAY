# R3PLAYX v2.9.2

## My Music

- Refreshed Liked Songs banner with larger covers and clearer playback actions.
- Compact, keyboard-accessible Library tabs with a selected pill and improved dark-mode contrast.
- Weekly artists use round portraits and remain above the Library.
- Album and playlist names stay visible; loading, error, empty and guest states are clearer.
- Login opens on request, supports Escape and restores keyboard focus.
- Improved playlist search contrast and track-row spacing.

## Audio cache and reliability

- Audio Cache Streaming v2 downloads in Electron background jobs directly to temporary files,
  with incremental SHA-256, metadata from disk and atomic finalization. Playback never waits
  for caching and continues if a cache job fails.
- Bounds concurrency, queued jobs, size, timeouts and redirects; validates CDN/DNS hops.
- Preserves track, quality, source, format, bitrate, sample rate, bit depth, hash and filename.
  Lossless, Hi-Res and audio-effect variants remain separate without silent downgrades.
- Cleanup tolerates locked orphan files and initialization can retry after failure.
- Desktop and standalone Unblock caches share a 120-second TTL and URL validation.
- Cached fallback audio is reused after NetEase fails, retaining unknown quality.
- Bulk database helpers handle empty arrays, parameterize queries and name insert columns.
- Context-menu dismissal and trigger identity are more reliable.

## Validation and known limitations

The Windows release pipeline runs web/desktop tests and typechecks, server/workspace builds,
packaging, packaged runtime/streaming probes and an application startup smoke test.
My Music was also checked in Chromium with mocked API data in light/dark themes and narrow layouts.

Real-CDN validation remains partial: a small Kuwo MP3 transfer/cache/Range probe passed, but
this does not establish full-song playback or production cache hit rate. NetEase 320K,
Lossless, Hi-Res, AAC and audio-effect full-CDN cases remain unverified with authorized URLs.
The installer is unsigned.

## Upgrade and downgrade

Back up your profile before upgrading. v2.9.2 adds a hash column to AudioVariant and uses
streaming cache filenames. To downgrade to v2.9.1, restore the backup or, with the app stopped,
reset only the AudioVariant cache table following docs/audio-cache-v2.9.md. Retain account,
playlist and settings tables. Simply installing the older binary is not a clean rollback.
